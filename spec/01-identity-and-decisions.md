Part of the [XmlEssentials spec](README.md).

Install story:

```bash
dotnet add package XmlEssentials
```

```csharp
using CloudNimble.Text.Xml;
using CloudNimble.Text.Xml.Serialization;

string xml = XmlSerializer.Serialize(person);
Person? p = XmlSerializer.Deserialize<Person>(xml);
```

Name collision with `System.Xml.Serialization.XmlSerializer` is **accepted**. This library does not import BCL XML. Consumers who only `using CloudNimble.Text.Xml` get our type. SDK implicit usings do **not** include `System.Xml.Serialization`. CS0104 happens only when both namespaces are imported in the same file — the same situation as `Newtonsoft.Json.JsonSerializer` vs `System.Text.Json.JsonSerializer`.

The same collision policy applies to `XmlDocument`, `XmlElement`, `XmlException`, `XmlAttribute`, `XmlNode`. Ours live in `CloudNimble.Text.Xml`. BCL types are not referenced.

**Do not use** package id `CloudNimble.XmlEssentials` (the NuGet id is `XmlEssentials`) or namespace `CloudNimble.XmlEssentials` (the namespace is `CloudNimble.Text.Xml`). The assembly and projects **are** `CloudNimble.XmlEssentials`.

## Key decisions

| # | Decision | Rationale |
| --- | --- | --- |
| K1 | High-level type is `XmlSerializer` (static), not `XmlDataSerializer` | STJ parallel. Collision with BCL is accepted. #125299 used `XmlData*` to dodge BCL; we are not the BCL. |
| K2 | Package `XmlEssentials`, assembly `CloudNimble.XmlEssentials`, namespace `CloudNimble.Text.Xml` | Package/assembly follow Essentials. Namespace is the STJ parallel and a `using` swap hedge. |
| K3 | Zero BCL XML, including internally | "BCL XML is dead" for this product. Own UTF-8 reader/writer. |
| K4 | Own attribute family in `CloudNimble.Text.Xml.Serialization` | Reusing BCL attributes forces `using System.Xml.Serialization` and CS0104, and is a BCL XML dependency on DTO files. |
| K5 | `[XmlInclude]` = STJ `[JsonInclude]` (non-public members). Known derived types = `[XmlDerivedType]`. | BCL `[XmlInclude]` means known types. Do not collide those semantics. |
| K6 | `[XmlRoot]`, `[XmlAttribute]`, `[XmlElement]`, `[XmlArray]`, `[XmlText]` in **our** namespace | XML needs element-vs-attribute. STJ does not. We add XML-shaped attributes on top of the STJ set, not instead of it. |
| K7 | Default mapping: public property → child element named by naming policy. `XmlSerializerOptions.DefaultPropertyMapping` (`Element` / `Attribute`) is the blanket switch so callers need not annotate every member. `Attribute` maps **unannotated simple** members as XML attributes; nested objects stay elements and their simple members also become attributes (the option is per bind, so it recurses). Collections stay elements. Per-member `[XmlElement]` / `[XmlAttribute]` / `[XmlText]` still win. | STJ property → JSON property. XML analogue is child element, not attribute. A global attribute default is the STJ-shaped way to hit attribute-heavy XML without BCL-style opt-in on every property. |
| K8 | Collections default to **repeated elements with the property name** (STJ-like). `[XmlArray]` opts into a wrapper, and `[XmlArrayItem]` names the items inside one; without `[XmlArray]` it has no effect. | STJ has no wrapper. Most "modern" XML APIs still need wrappers; they are opt-in, not default. |
| K9 | Default member order is most-base then most-derived, declaration order within each type. `[XmlPropertyOrder]` may **interleave** base and derived. That interleave is the break from BCL XSD extension (Order is per-class; derived may only append). | Matches the mapping section. Default walk is XSD-shaped; opt-in Order is why this library exists (ModernXmlSerializer). |
| K10 | Mixed content: reader/writer/DOM yes. Serializer mapping via `[XmlMixed]` content lists (ordered nodes / DTOs). Types without `[XmlMixed]` skip or disallow unexpected mixed input per [XML fidelity](02-xml-fidelity.md#mixed-content). | XML mixed content has no JSON analogue; `[XmlMixed]` is the mapper for it. |
| K11 | Simple content (attributes + `[XmlText]`) is supported | `<Price currency="USD">19.99</Price>` is common and fits the property model. |
| K12 | `xsi:nil` is first-class (`WriteNil`, nillable properties), implemented by this stack | JSON `null`. We do not reference `System.Xml`. |
| K13 | No DTD → XXE closed | Presence of `<!DOCTYPE` (or other `<!` markup besides comments) is `XmlException`. |
| K14 | UTF-8 only. Other encodings declared in the XML declaration fail clearly. Reader **accepts** an optional BOM. Writer **`EmitByteOrderMark` defaults to `false`**. When `true`, the writer emits `EF BB BF` once at the start of the document (before the declaration). | STJ does not BOM UTF-8 by default. BOM is a file/sniffer interop knob (`OmitXmlDeclaration` + Windows/Excel/EDI). |
| K15 | Lexical forms are XSD 1.0 datatypes, invariant culture, with `whiteSpace = collapse` applied first; one implementation (`XmlLexical`) serves reader, DOM, and serializer. **`decimal` read and write reject exponent** (`1E+2` is `float`/`double`, not XSD decimal). | `boolean` true/false/1/0; numbers without group separators; `xs:dateTime` / `xs:date` / `xs:time` / `xs:duration`; `xs:base64Binary`. |
| K16 | `Dictionary<TKey,TValue>` / `IDictionary<,>` map as STJ objects do. Default: string keys that are valid XML names after `DictionaryKeyPolicy` become child element names; otherwise repeating `<Key>`/`<Value>` entries. `[XmlExtensionData]` remains a bag, not a map. | JSON object analogue. |
| K17 | Source generator packed inside `XmlEssentials` nupkg | STJ-style. No extra `PrivateAssets` package. |
| K18 | Reflection gated by `XmlSerializer.IsReflectionEnabledByDefault`; context overloads have no AOT warning | Match STJ. |
| K19 | Object `DeserializeAsync(Stream)` is buffer-then-parse (STJ). `DeserializeAsyncEnumerable` / `SerializeAsyncEnumerable` stream items (including `topLevelValues`). Reader `IsFinalBlock` resume is required. Public `XmlReaderState` is STJ-shaped (`Options` only); **implementation must snapshot** element stack, namespace scopes, partial token, and positions — see [04](04-api-reader.md#xmlreaderstate-implementation-contract). | Match STJ async shapes. |
| K20 | PackageId = `$(MSBuildProjectName.Replace('CloudNimble.', ''))` on the primary library → `XmlEssentials` | Assembly `CloudNimble.XmlEssentials` already strips to the right package id. |
| K21 | **100% line** on `CloudNimble.XmlEssentials.dll` is the CI **fail** gate. **Branch** is also a fail gate at **100%** since PR 4 (it started as a reported 80% ratchet; the tokenizer reached 100% without exclusions, so the floor was raised and nothing is branch-excluded). **Host is MTP** (`global.json` `test.runner: Microsoft.Testing.Platform`). Collection: `Microsoft.Testing.Extensions.CodeCoverage` via `dotnet test --coverage --coverage-output-format cobertura --coverage-output artifacts/coverage/coverage.cobertura.xml`. That extension **does not fail** on its own. Fail gate: `dotnet run src/coverage-gate.cs -- artifacts/coverage/coverage.cobertura.xml`. **Not** `coverlet.runsettings` / VSTest DataCollector. Ratchet starts in [PR 2](22-pr-plan.md). Tests are never written to reach a line or branch ([testing rule 5](14-testing.md#rules)). | MTP ignores coverlet DataCollectors. |
| K22 | Benchmarks cache BCL `XmlSerializer` instances. Label BCL column “BCL defaults (wrapped collections)” unless BCL attributes pin the infoset. STJ is a sidecar (XML tax vs JSON), not a win/loss. | ModernXmlSerializer's benchmark was dishonest. Mapping mismatch is fairness, not a bug. |
| K23 | TFMs `net10.0;net11.0` | Match ClaudeEssentials. |
| K24 | Comments and whitespace: the zero value of `XmlCommentHandling` is `Allow` and of `XmlWhitespaceHandling` is `Significant`, and the zero value is the default for the reader and the DOM, in `default` and in `new()` alike. The serializer skips both by default (`ReadCommentHandling = Skip`, `WhitespaceHandling = Insignificant`). | No surprises on a round trip: XML that is read and written back keeps its comments and its layout. XML 1.0 section 2.10 requires a processor to pass all non-markup characters to the application. An object has no place for a comment or for indentation, so the serializer skips them. Decided 2026-11-23; before that the reader and DOM skipped both and `default` options disallowed comments. |
| K25 | Root element name = type name via naming policy, overridable `[XmlRoot]` in our namespace. Type names are those `System.Xml.Serialization` writes: the XML Schema name for a built-in type (`int`, not `Int32`), `ArrayOf` + item name for every collection, and the CLR name otherwise ([decision 70](24-doc-findings-resolution.md)). | Not `[XmlSerializableRoot]`. Until 2026-11-24 primitive roots used the CLR name, for no recorded reason. |
| K26 | Element name comparison is `{local name, namespace URI}`, never prefix | Prefix is serialization sugar. |
| K27 | Writer writes `<e/>` from `WriteEndElement()` when an element has no content; `WriteFullEndElement()` writes `<e></e>` | Match BCL `XmlWriter` usefully without taking a dependency. |
| K28 | Empty element with no `xsi:nil` deserializes as empty string / default struct / empty collection, **not** null | `xsi:nil="true"` is null. This distinction is the XML data model STJ does not have. |
| K29 | Case-sensitive names by default; `PropertyNameCaseInsensitive` is an explicit interop option | XML 1.0 names are case-sensitive. |
| K30 | Generator supports **internal types in the consuming compilation** only (not friend assemblies unless those types are compiled in the same compilation). | Improvement over BCL `XmlSerializer`. Friends are not “in the compilation.” |
| K31 | `Serialize(null)` of a nillable reference type writes the root element with `xsi:nil="true"`. An ignore condition does not apply to the root: a document needs its document element. Value-type null is impossible. | STJ writes JSON `null`; XML analogue is a nillable root. |
| K32 | On every max-* **except** `MaxDocumentByteCount`, `0` means “apply the default from the DoS table.” `MaxDocumentByteCount` `0` stays unbounded. Stream/document buffering **enforces** the cap while growing, not after. | `default(XmlReaderOptions)` is all zeros; 0-byte comments would otherwise reject every document. |
| K33 | `XmlNumberHandling` is `[Flags]` with `Strict = 0` and `AllowNamedFloatingPointLiterals = 1` only. Options default is `AllowNamedFloatingPointLiterals` (XSD INF/NaN). No `WriteAsString` / `AllowReadingFromString`. | JSON-string numbers have no XML analogue. |
| K34 | No `EncodeInvalidCharsAsHex` public API. Char legality follows the document version (1.0 or 1.1). | [XML 1.0 and 1.1](02-xml-fidelity.md#xml-10-and-11). |
| K46 | XML **1.0 and 1.1**. One tokenizer. Reader version comes from the declaration (omitted ⇒ 1.0). Writer/serializer `XmlVersion` defaults to 1.0. Not two reader types. 1.1 is not a superset of 1.0 (NEL, RestrictedChar, `xmlns:p=""`). | BCL `XmlReader`/`XmlWriter`/`XmlSerializer` never implemented 1.1. |
| K47 | XSD support is **compile-time codegen**, not runtime `XmlSchemaSet`. `AdditionalFiles` `*.xsd` → POCOs + our attributes + `[XmlSerializable]` entries; the existing serializer generator then emits AOT ser/deser. No schema load, no `XmlUrlResolver`, no DTD, at runtime. | Same AOT story as the type generator. Runtime XSD validation is a different product. |
| K35 | Multiple `[XmlElement<T>]` on one member, or multiple `[XmlArrayItem<T>]` on a wrapped collection = per-member polymorphic choice: each element name stands for a type. Every one names its type. Complements type-level `[XmlDerivedType]`, and stands in its place on that member (implemented by decision 74 in `24`). | BCL choice pattern; otherwise `AllowMultiple = true` is unspecified. |
| K36 | `[XmlPropertyOrder]` / `XmlElement.Order` / `XmlArray.Order`: unset is **`-1`**, not `0`. Members with explicit order (`>= 0`) sort first by order (stable). Members with unset order follow in flattened declaration order. | BCL uses `-1` for unset; default `0` would shove unspecified members to the front. |
| K37 | Missing `required` / `[XmlRequired]` / required constructor parameter on deserialize → `XmlException`. `RespectRequiredConstructorParameters` default **true**. | STJ throws; XML must too. |
| K38 | Serializer `WhitespaceHandling` is forwarded to the `Utf8XmlReader` used on deserialize only. Serialize never preserves significant whitespace (indent is cosmetic). | Options property is not a mapper mixed-content feature. |
| K39 | Test package id is **`Breakdance.Assemblies` 8.*** (not `CloudNimble.Breakdance.Assemblies`). Local Breakdance repo is 9.0.0-preview; 8.* matches EasyAF. | ClaudeEssentials/EasyAF strip `CloudNimble.` from Breakdance project names too. |
| K40 | Public XML comments from the PR that introduces each public type. PR 1 sets `TreatWarningsAsErrors` and `NoWarn` **CS1591** on projects that do not yet have public API. Remove CS1591 from `NoWarn` for the runtime library in the same PR that adds its first public type (PR 2). | Otherwise PRs 2–9 cannot compile under `GenerateDocumentationFile`. |
| K41 | Source generator ships **both** `XmlSourceGenerationMode.Serialization` and `Metadata`. `Default` = `Metadata \| Serialization` (STJ). What each mode emits is K52. | Same split as STJ. |
| K42 | Source-gen interceptors rewrite `XmlSerializer.Serialize<T>(value)` / `Deserialize<T>(input)` call sites that pass **no options** to the type-info overload of the matching context's `Default` instance. A call that passes an `XmlSerializerOptions` argument is never rewritten: options carry the caller's resolver, converters and naming, and the call runs as written. | A redirected call must write the document the same call wrote before the context existed. |
| K43 | `ReferenceHandler` (`Preserve` / `IgnoreCycles`). Preserve uses attributes in namespace `urn:CloudNimble.Text.Xml:refs` (`id`, `ref`), not SOAP `href`. | STJ `$id`/`$ref` analogue. |
| K44 | `PipeReader` / `PipeWriter` overloads match STJ. | Same I/O surfaces. |
| K45 | `XmlSerializerOptions.Default`, `.Web`, `.Strict`, and `.Bcl` (the defaults of `System.Xml.Serialization.XmlSerializer`; decision 71 in `24`). `PascalCase` naming policy. `DictionaryKeyPolicy`, `AllowDuplicateProperties`, `GetConverter`, `TryGetTypeInfo` / `TryGetTypeInfo<T>`. | Same options surface as STJ. |
| K48 | No `AllowOutOfOrderMetadataProperties`. Do not add it. Reference ids, references (K43) and type discriminators are attributes or the element name, never child elements, and they are accepted in any position. | In System.Text.Json the metadata (`$id`, `$ref`, `$type`) are properties, which have an order. XML 1.0 section 3.1 says the order of attributes is not significant, so the question cannot arise, and an option that rejected one order would contradict the specification. `MetadataAttributes_AreAcceptedInAnyPosition` pins it; see decision 49 in [doc findings resolution](24-doc-findings-resolution.md). |
| K49 | No `XmlNilHandling` and no `NilHandling` option. Do not add them. A null that is written is always an element marked `xsi:nil="true"`. Whether a null member is written is `DefaultIgnoreCondition` and `[XmlIgnore(Condition = …)]`, with the values and meaning of `JsonIgnoreCondition`. A null collection item, dictionary value and root are always written. A null is never written as an empty element. | `xsi:nil` is how XML spells null, so the one option about nulls is the one System.Text.Json has. An empty element read back as an empty string, or not at all for a number. See decision 44 in [doc findings resolution](24-doc-findings-resolution.md). |
| K50 | An attribute that names a type takes it as a type argument, and has no form that takes `typeof`: `[XmlSerializable<T>]`, `[XmlConverter<TConverter>]`, `[XmlDerivedType<T>]`, `[XmlElement<T>]`, `[XmlArrayItem<T>]`. Do not add a `Type` constructor parameter to an attribute. Where the serializer has to find the attribute without knowing the type argument, an abstract non-generic base class is the form it looks for, and only the generic class derives from it. | The compiler checks the type: a converter must derive from `XmlConverter` and have a public parameterless constructor, and it is created with `new`, not through reflection. With `typeof`, a wrong type compiled and failed at run time. See decision 43 in [doc findings resolution](24-doc-findings-resolution.md). |
| K51 | `PreferredObjectCreationHandling` defaults to `Replace`, so a member with no setter is not read, a collection included. `XmlObjectCreationHandling.Populate`, on the options or with `[XmlObjectCreationHandling]`, adds to the collection, dictionary or object the member holds. Do not fill a collection with no setter by default. | The values, the default and the rules are those of `JsonObjectCreationHandling`. `System.Xml.Serialization` fills such a collection always; the migration guide says so. See [object mapping](09-object-mapping.md#object-creation-handling) and decision 46 in [doc findings resolution](24-doc-findings-resolution.md). |
| K52 | Source generation emits **metadata** (`XmlObjectInfoValues<T>`, `XmlPropertyInfoValues<TValue>`, `XmlParameterInfoValues`), and the one runtime engine reads and writes from it. The generator writes no converter and no code that reads XML. `Default` adds a write fast path that is used only when the options allow it; `Serialization` alone has only the fast path and throws `InvalidOperationException` for anything else; the mode on `[XmlSerializable<T>]` overrides the context's. `init`, `required` and non-public members and constructors are reached through `[UnsafeAccessor]`. See [single engine](25-single-engine-metadata.md). | It is what System.Text.Json does. Two engines meant every feature was written twice or refused in one of them: derived types, member converters, mixed content, references, populating, and options that differed from the compiled ones were all refusals. With one engine a generated context cannot disagree with the reflection resolver, and every mode is Native AOT-safe. Do not add generated read code or a second set of mapping rules. |
| K53 | Members of the same name in a type and its base types follow System.Text.Json: a member is governed by the attributes written on it (an override inherits none); an override or a `new` member is serialized in place of the base member; an ignored override hides the property it overrides and an ignored `new` member does not; unrelated members with one XML name are an error. See [object mapping](09-object-mapping.md#members-of-the-same-name). | Decided by the owner on 2026-11-23, from a probe of .NET. The reflection resolver had inherited `[XmlIgnore]` and nothing else, and threw for any plain override. |
| K54 | **Predictable normalization.** What is read and written again keeps its infoset and the layout between its nodes; everything else that is rewritten is rewritten by a named setting of the writer that applies to every element the same way. The settings are `EmptyElementStyle`, `AttributeStyle` with `AttributesPerLine`, `NewLine` (every line break, with the two values `JsonWriterOptions.NewLine` accepts) and `OmitXmlDeclaration`, on `XmlWriterOptions` and under the same names on `XmlSerializerOptions`. This replaces "what is parsed is written back byte for byte", which was never true of white space inside tags, quotes, line endings or character references. See [XML fidelity](02-xml-fidelity.md#round-trip-guarantees). |
| K55 | **XPath 1.0 over the row store; a node is an id in document order.** A node of the read-only `XmlDocument` is a 64-bit id derived from its row (namespace nodes in the low half), so ids sort in document order and a node-set is an ascending `long[]`. The navigator reads names and values as UTF-8 from the rows; the only thing it adds to a document is a parent table, built on first use. The grammar, the conversions and the core functions are ported from Xemele; the navigator and the evaluator are new. See [XPath](27-xpath.md). | Xemele's navigator copies the whole document into strings for each evaluation. The row store already is a document-order snapshot with an end index for each element, so copying it gains nothing, and comparing `@id = 'x'` as bytes needs no transcoding. |
